# SmartScribe skin also covers literal Eleos-navy (#293D87) CTAs, scoped by color not by feature

After ADR-0006 shipped (nav rail + launcher/pill only), a report named four CTAs — "Next," "Capture Session," "Select session," "Add suggestions to EHR" — as missing the skin. None of those actually use `#293D87`; they're all `#2d4ccd` (Eleos primary blue), a different color serving a different role (primary action buttons), and out of scope. Auditing the codebase for literal `#293D87` usage instead of going by button name turned up the real remaining cases, all in the EHR-overlay "Enhance" CTA family that floats on top of any EHR background: `EnhanceTooltip` and `InlineLaunchButton` (`EhrBackgrounds.jsx`), and `EnhancePointer`/`EnhanceInlineButton` (`components/enhance/`, plain TSX props components with no context access of their own).

We did not extend the skin to `MySessionsPanel`'s "Marked as Done" session-card strip (`ClinicianScene.jsx`, `background: activeTab === 'done' ? '#293D87' : '#01579B'`) even though it's a literal `#293D87` usage — it's a panel-internal category-color accent, not a CTA or a border, and ADR-0006 already established that sidebar panels keep default light Eleos styling absent a design reference. Treating "is it CTA-navy" rather than "is it any navy pixel" as the scoping question keeps this change matched to what was actually reported.

Mechanism: same `useSmartScribeSkin()` boolean as ADR-0006. `EhrBackgrounds.jsx` already sits inside the EHR provider tree (its sibling components call `useEhrContext()` for `clientName`), so `StackedFields` calls the hook directly and passes a `skin` prop down to the four Enhance components — `EnhancePointer`/`EnhanceInlineButton` take it as a plain prop (no context import) since they're presentational components reused elsewhere without assuming EHR context is available.

A review pass caught two things worth recording. First, every call site had re-derived its own `skin ? '#254A67' : '#293D87'` ternary inline, which is exactly how a usage site (`EnhancePointerToolbar`/`EnhancePointerToolbarWrapper` — a second, currently-unrendered consumer of `EnhancePointer`) got missed in the first pass despite `CONTEXT.md` claiming universal coverage. We centralized the mapping into a single `smartScribeColor(skinActive, defaultColor)` helper (`EhrContext.jsx`, exported alongside `useSmartScribeSkin`) that every usage site — including plain-prop TSX components, which import it as a pure function rather than a hook — now calls instead of re-deriving the ternary, so a future new usage site gets the color right by construction rather than by remembering to copy the ternary. Second, we wired `skin` through `EnhancePointerToolbarWrapper` → `EnhancePointerToolbar` → `EnhancePointer` for consistency even though that path is currently dead code (never rendered — see the "removed" comment in `ClinicianScene.jsx`); fixing it was a two-line change and removes a footgun for whoever revives it.
