# SmartScribe skin extends to sidebar panels and to literal #2d4ccd, superseding ADR-0006/0007's panel exception

Issue #78 asked to extend the SmartScribe skin (ADR-0006, ADR-0007) to the Companion Sidebar's panels — Activities (`MySessionsPanel`), Add Summary, Capture Session, Clients, Support/Quality — which both prior ADRs had deliberately left on default light Eleos styling because no design reference existed for a navy variant of any panel.

No design reference exists now either. Rather than invent one (the exact mistake ADR-0006 already made once with the Flash Screen splash), we re-scoped the question from "what should a navy panel look like" to "what does this skin already mean, applied everywhere it already appears": every literal Eleos-brand color the skin already recolors elsewhere, recolored consistently wherever it occurs, including inside panels. This required overturning two specific calls the prior ADRs made:

1. **ADR-0007's `MySessionsPanel` "Marked as Done" exception.** ADR-0007 found this strip used literal `#293D87` but chose not to skin it, reasoning it was "a panel-internal category-color accent, not a CTA or a border." We overturned that: it now goes through `smartScribeColor()` like every other `#293D87` site. The distinction ADR-0007 drew (CTA/border vs. category accent) added a second scoping axis on top of "is it this literal color" — simpler to have one axis only.
2. **ADR-0006's "sidebar panels keep default light Eleos styling."** That covered panels having no navy at all. We extended the skin's color-literal scoping (already established for `#293D87`) to the sidebar's other Eleos-brand color, `#2d4ccd` (Eleos primary blue) — every literal `#2d4ccd`/`#2D4CCD` and its `rgba(45,76,205,*)` form, across every sidebar-panel component, not just the CTA-shaped ones ADR-0007 had explicitly named as out of scope (`Next`, `Capture Session`, `Select session`). Those three were only ever "out of scope" because they're `#2d4ccd`, not `#293D87` — a distinction that mattered when the skin covered exactly one literal color. Once the skin covers both of the app's Eleos-brand colors, that exclusion no longer has a reason to exist.

This is still a color-literal rule, not a panel-redesign: nothing about a panel's layout, copy, or non-brand colors (grays, semantic status colors, EHR-strip teal `#01579B`, etc.) changed. A panel with no `#293D87` or `#2d4ccd` in it today still renders identically under the skin.

Mechanism: unchanged from ADR-0006/0007 — `smartScribeColor(skinActive, defaultColor)` for hex literals, and a sibling `smartScribeRgb(skinActive, defaultRgb)` (`EhrContext.jsx`) for the `rgba(r,g,b,alpha)` form used in shadow/glow tints, so a shadow tint can swap navy without needing a hex color at that call site. `SMARTSCRIBE_NAVY_RGB` is derived from `SMARTSCRIBE_NAVY` via a `hexToRgb()` helper rather than hand-duplicated, so the two can't drift. The repeated 5-layer Enhance-CTA box-shadow recipe was consolidated into one exported `smartScribeEnhanceShadow()` helper used by all four Enhance-family call sites, rather than copy-pasted per usage site — the same "centralize so a new call site can't get it wrong" reasoning ADR-0007 used for `smartScribeColor` itself.

Components under `ClinicianScene.jsx`'s panels call `useSmartScribeSkin()` directly (matching the pattern already used by `TagField`, `MySessionsPanel`, `CompanionLaunchButton`, `NavRailIcon`), rather than threading a `skin` prop down — that prop-threading pattern stays reserved for the Enhance CTA family (`EnhancePointer`, `EnhanceInlineButton`), which are plain presentational components reused without guaranteed EHR-context access (ADR-0007).
